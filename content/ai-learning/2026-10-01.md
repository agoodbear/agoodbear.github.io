## 今日最有感的事

今天在 Threads 連續看到三篇 Opus 5.5 做影音的貼文，我都轉到 LINE 收件匣，各留了一句備註：「動畫解析 feedback 到 skill 裡面」「動畫影片學習」「動畫暴力解析，然後逆向工程 feedback 到 skill 裡面」。

**先補一點背景給非工程師讀者。**
我平常用 Claude Code 做 ECG 教學動畫，並把累積的做法整理成一份 skill。skill 是寫給 AI 讀的操作手冊，下次做動畫時，AI 會先讀這份手冊，不用每次從頭摸索。「feedback 到 skill」的意思是：看到別人做得好的作品，就把手法拆出來，補進這份手冊。

### 三篇貼文各自講了什麼

**[pan_0709](https://www.threads.com/@pan_0709/post/Dd5lzGUnHD2)**：他說自己只提供了一個音檔，剪輯、動畫、操作教學、封面和文案都由 Opus 5.5 完成，成品是一支 10 分鐘的影片。整個過程約 1 小時，用掉 100 美元額度的 25%。這篇是三篇裡迴響最大的，瀏覽 71.3K、讚 1.8K、分享 1.5K。

**[pound0423](https://www.threads.com/@pound0423/post/Dd6eXh4iaCk)**：他用 Claude Opus 5.5 做了一個視覺特效工具，上傳影片或圖片後，一鍵就能加上各種故障（glitch）特效，目標使用者是影片創作者。他說晚點會開源到 GitHub，但他不分享連結，只給指令，原話是「受之以魚不如授之以漁」。

**[charles__tseng](https://www.threads.com/@charles__tseng/post/Dd6Bo7zk4Td)**：他試了 Opus 5.5 搭配 ElevenLabs MCP，用一個 one-shot prompt 就做出成品，自己的評語是「真的好扯」。補個背景：MCP 是讓 AI 呼叫外部工具的接頭，ElevenLabs 是以語音合成聞名的服務。接上之後，AI 可以自己去叫配音，不用人在兩個工具之間來回搬檔案。

### 真正值得看的是：三篇都只有結果

我原本想照備註說的那樣，把三支影片拆開來逆向工程。但這輪只讀到貼文文字，影片本身和附圖都沒抓到。第一篇沒附外部連結，第二篇的 GitHub 還沒公開，第三篇的 prompt 也沒貼出來。

**更直白地說，今天收到的是「AI 能做到什麼」的證據，手法的證據幾乎沒有。** 三篇加起來，能直接寫進 skill 的內容大概只有兩樣：

- **成本參考點**：一支 10 分鐘的影片，花 1 小時、約 25 美元。前幾天我做 Wellens 動畫時，讀 skill 和不讀 skill 兩組各跑一次，一支 84 秒的動畫大約 30 分鐘、6 美元多。兩者的工作內容差很多，不能直接比單價，但至少有了「長片大概落在哪個量級」的概念。
- **流程的形狀**：pan_0709 從音檔出發，charles__tseng 把配音交給 MCP。我現在的做法剛好反過來，先做畫面，最後再用 Gemini TTS 生成旁白。從聲音開始、讓畫面去配合聲音，是一條我還沒試過的路。對旁白節奏很重要的教學片來說，這條路可能更自然。

### 「授之以漁」反而是最實際的提醒

pound0423 那句「我不分享連結，只給指令」，原本只是他個人的分享態度，但剛好說中我這輪的處境：成品看再多，沒有 prompt 和原始碼，就很難反推回手法。

**這代表下次在 Threads 收這類貼文，比起讚數，更要先看留言區有沒有 prompt、有沒有 repo。** 有的話值得拆，沒有的話就先當成靈感存著，不用急著派子代理去暴力解析一個看不到的影片。等 pound0423 的 GitHub 真的開源，那一篇會是三篇裡最有機會拆出具體做法的。
